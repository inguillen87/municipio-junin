Gobierno de identidades

Administración bloqueada hasta completar su contrato productivo

Esta pantalla dejó de simular usuarios, auditorías, invitaciones y configuraciones en el navegador. El backend autoriza contra el usuario vigente en base de datos, pero la consola de administración no se habilitará hasta contar con API serverless versionada, auditoría y pruebas de escritura reales.

Sin operaciones de alta, baja o cambio de rol disponibles

Condiciones de habilitación

El módulo se abrirá por etapas y con rollback verificable. No se almacenan configuraciones administrativas en localStorage.

01
API única de administraciónContrato serverless para usuarios, tenants, estados y auditoría; sin depender de un servidor Express separado.
02
Autorización y revocación autoritativasUsuario activo, rol, tenant y estado municipal revalidados en base de datos para cada operación protegida.
03
Auditoría transaccionalCada cambio debe registrar actor, tenant, campos modificados, resultado y correlación de solicitud.
04
Pruebas de entornoAlta, downgrade, desactivación, tenant suspendido, error de persistencia y rollback probados contra el entorno de despliegue.
