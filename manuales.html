Manual: Dashboard Ejecutivo

Archivo: index.html · Audiencia: Intendente, jefes de área

▶ Abrir módulo

¿Qué muestra?

📈KPIs en tiempo real: empleados, gasto mensual, horas extra, reclamos
💰Gráficos de evolución de gastos por mes y por secretaría
⚠️Alertas automáticas cuando una secretaría supera el presupuesto
📋Feed de actividad reciente del sistema

¿Cómo actualizar los datos?

Actualmente los datos son de demostración (mock). Para conectar datos reales:

js/data.js — Cambiar datos mock por API
// ACTUAL (datos de demo):
const MUNICIPIO_DATA = { gastoTotal: 284500000, empleados: 1247, ... };

// FUTURO (conectar a API real):
const MUNICIPIO_DATA = await fetch('http://localhost:3001/api/dashboard').then(r => r.json());

Problemas comunes

❓ Los gráficos no cargan
Verificar que chart.js cargó desde el CDN. Si hay problemas de internet, copiar chart.umd.min.js localmente y cambiar el src.
❓ Los números no se actualizan
Son datos de demo en js/data.js. Editar ese archivo o conectar la API para datos reales.

Funcionalidades

1
Ver nómina de empleados
Tabla con todos los empleados, secretaría, cargo, sueldo y estado. Usar los filtros de secretaría y estado para buscar.
2
Agregar un empleado nuevo
Click en + Nuevo Empleado → Completar el formulario → Guardar. El sistema genera legajo automático.

Click en el ícono 📋 de la fila del empleado → Se descarga el PDF del recibo con membrete municipal.
4

5
Control de asistencia (futuro)

¿Cómo importar empleados desde Excel?

Formato del Excel de importación
Columna A: Legajo (ej: L-0001)
Columna B: DNI (ej: 28456789)
Columna C: Apellido y Nombre
Columna D: Secretaría
Columna E: Cargo
Columna F: Fecha de ingreso (dd/mm/yyyy)
Columna G: Sueldo bruto
❓ No aparece un empleado en la lista
Verificar los filtros activos. Los filtros de secretaría y estado pueden estar ocultando registros. Click en "Limpiar filtros".
❓ El PDF del recibo no se descarga
Verificar que jsPDF cargó desde el CDN. Revisar la consola del browser (F12) por errores.

Manual: Atención Vecinal

Archivo: vecinos.html · Audiencia: Operadores de atención al vecino

▶ Abrir módulo

Registrar un reclamo vecinal

1
Click en "Nuevo Reclamo"
Botón azul en la parte superior derecha.
2
Completar el formulario
DNI del vecino → Nombre → Tipo de reclamo → Área responsable → Dirección exacta → Descripción.
3
Guardar
El reclamo queda en estado "Pendiente" y aparece en la tabla. Se le asigna un número automático (#5001, #5002, etc.)
4
Cambiar el estado
Click en el ícono ✏️ de la fila → Cambia de Pendiente → En proceso → Resuelto.

Clasificación automática con IA

El módulo IA Lab → Clasificador permite que la IA categorice el reclamo automáticamente al describir el problema en lenguaje natural. No es necesario seleccionar el tipo manualmente.

Gestión de turnos

Tab "Turnos" → Ver agenda del día → Click en "Reservar Turno" para agregar un nuevo turno. Los estados son: Confirmado / Pendiente / Atendido.

❓ ¿Cómo filtrar reclamos de una zona específica?
Usar el buscador de la tabla (campo "Buscar vecino o dirección") y escribir el nombre del barrio o calle.
❓ ¿Se puede exportar la lista de reclamos?
Sí. Ir a Exportar Reportes → Seleccionar "Reclamos Vecinales" → Exportar PDF o Excel.

Manual: Servidor e Infraestructura

Deployment en producción en el rack del municipio

Deployment con Docker Compose (producción)

docker-compose.yml
version: '3.9'
services:
  web:
    image: nginx:alpine
    ports: ["80:80", "443:443"]
    volumes:
      - ./municipio-junin:/usr/share/nginx/html
      - ./nginx.conf:/etc/nginx/nginx.conf

  api:
    image: node:20-alpine
    working_dir: /app
    command: node server.js
    ports: ["3001:3001"]
    environment:
      DATABASE_URL: postgresql://municipio_admin:PASS@db:5432/municipio_db

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: municipio_db
      POSTGRES_USER: municipio_admin
      POSTGRES_PASSWORD: CAMBIAR_EN_PRODUCCION
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports: ["5432:5432"]

  ollama:
    image: ollama/ollama
    ports: ["11434:11434"]
    volumes:
      - ollama_data:/root/.ollama

volumes:
  postgres_data:
  ollama_data:

Manual: Backups y Recuperación

Estrategia 3-2-1 para proteger los datos del municipio

🔴 CRÍTICO: Los datos de empleados, reclamos y gastos son información sensible y deben respaldarse diariamente. Una pérdida de datos sin backup puede causar un problema legal grave.

Estrategia de backup 3-2-1

3
Copias de los datos
Siempre mantener 3 copias del backup
2
Tipos de almacenamiento
Servidor principal + disco externo
1
Copia externa
Un backup en ubicación física distinta (ej: pen drive en intendencia)

Script de backup automático

backup.sh — ejecutar con cron cada día a las 2AM
#!/bin/bash
DATE=$(date +%Y-%m-%d)
BACKUP_DIR="/backups/municipio-junin"
mkdir -p $BACKUP_DIR

# Backup PostgreSQL
docker exec municipio_db pg_dump -U municipio_admin municipio_db \
  | gzip > "$BACKUP_DIR/db-$DATE.sql.gz"

# Backup archivos del sistema
tar -czf "$BACKUP_DIR/files-$DATE.tar.gz" /var/www/municipio-junin/

# Eliminar backups más viejos de 30 días
find $BACKUP_DIR -type f -mtime +30 -delete

echo "✅ Backup completado: $DATE"

Verificar que el backup funciona

Guía de Problemas y Soluciones

Troubleshooting — Lo que puede salir mal y cómo solucionarlo

🔴 El sistema no abre en el navegador
  1. Verificar que el servidor Python esté corriendo (PowerShell con el comando de inicio)
  2. Probar http://localhost:8181 exactamente (no https, no sin puerto)
  3. Si el puerto 8181 está ocupado: usar 8182, 8080 u otro puerto libre
  4. Deshabilitar firewall temporalmente para probar
🔴 Los modelos de HuggingFace no cargan
  1. Verificar conexión a internet (los modelos se bajan de HuggingFace la primera vez)
  2. Revisar la consola del browser (F12 → Console) por errores CORS o de red
  3. Limpiar caché del browser y reintentar
  4. Si persiste, descargar los modelos manualmente y servirlos localmente
🔴 El micrófono no funciona
  1. Verificar que el browser tiene permiso de micrófono (ícono en la barra de direcciones)
  2. Solo funciona en Chrome o Edge (no Firefox ni Safari)
  3. Usar Whisper (Tab en ia-hf.html) como alternativa de mayor calidad
🔴 El PDF no se genera o descarga
  1. Verificar que jsPDF cargó correctamente (F12 → Network → buscar jspdf)
  2. Verificar que el browser permite descargas (sin bloqueador de popups activo)
  3. Probar en modo incógnito para descartar extensiones bloqueadoras
🔴 El OCR no lee el texto correctamente
  1. El documento debe tener buena calidad de imagen (mínimo 150 DPI)
  2. Tesseract funciona mejor con texto negro sobre fondo blanco
  3. Para documentos en color, escanear en blanco y negro mejora resultados
  4. El OCR tarda entre 10-60 segundos según el tamaño de la imagen
🔴 La base de datos no conecta (producción)
  1. Verificar que Docker está corriendo: docker ps
  2. Verificar que el contenedor de PostgreSQL está activo: docker ps | grep db
  3. Revisar logs: docker-compose logs db
  4. Probar conexión: psql -h localhost -U municipio_admin -d municipio_db
